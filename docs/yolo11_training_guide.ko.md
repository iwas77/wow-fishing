# 낚시찌 YOLO11 학습 가이드

이 문서는 `src/train_bobber_detector.py`가 무엇을 하는지, 왜 필요한지, 어떻게 더 잘
만들 수 있는지를 설명합니다. 어려운 말이 나오면 바로 쉬운 비유를 붙였습니다.

## 1. 한 줄 요약

이 프로젝트는 게임 화면에서 **낚시찌(`bb`)를 찾아 네모 상자로 표시하는 눈**을
만듭니다. 사진과 “찌는 여기 있어요”라고 적은 메모(CSV 라벨)를 보여 주면,
YOLO11이라는 인공지능이 찌를 찾는 법을 연습합니다.

아이에게 설명하면 다음과 같습니다.

1. 사진은 그림책의 한 페이지입니다.
2. 라벨은 선생님이 찌 주변에 그어 둔 네모입니다.
3. 모델은 그림을 보고 네모를 그리는 연습을 합니다.
4. 처음 보는 게임 화면에서도 찌를 찾아 네모를 그리면 성공입니다.

## 2. 이 프로젝트에서 사용하는 기술

| 기술 | 하는 일 | 쉬운 비유 |
| --- | --- | --- |
| Python 3.12 | 모든 프로그램을 실행하는 언어 | 로봇에게 말하는 언어 |
| Ultralytics | YOLO11의 학습과 추론 명령을 제공 | 로봇 눈 만들기 상자 |
| YOLO11s | 사진 속 물체와 위치를 함께 찾는 모델 | 찌 찾기 연습장 |
| PyTorch | YOLO11이 계산할 때 사용하는 엔진 | 로봇의 근육과 계산기 |
| Pillow | 사진의 가로·세로 크기를 읽음 | 그림의 크기를 재는 자 |
| OpenCV | 디버그 화면을 보여 줌 | 화면을 보여 주는 창 |
| pywin32 | Windows 게임 창을 캡처 | 게임 창의 사진을 찍는 손 |
| PyAutoGUI | 감지된 찌 위치로 마우스를 이동 | 로봇의 손 |

`ultralytics`를 설치하면 PyTorch 등 학습에 필요한 주요 패키지도 함께 설치됩니다.
GPU를 사용하려면 설치되는 PyTorch가 사용 중인 NVIDIA 드라이버/CUDA와 맞아야 합니다.
CPU에서도 실행은 가능하지만 학습과 추론이 훨씬 느립니다.

## 3. 필요한 파일과 디렉터리

```text
data/
  bobber/
    raw/
      annotations.csv       # 사람이 만든 원본 정답 메모
      images/               # CSV가 가리키는 80장의 학습 스크린샷
    yolo11/                 # 스크립트가 자동으로 다시 만드는 YOLO 형식 데이터셋
models/
  bobber/
    best.pt                 # 가장 성적이 좋았던 학습 결과물
runs/
  yolo11/bobber/            # 학습 기록, 그래프, 검증 결과, 임시 체크포인트
src/
  train_bobber_detector.py  # 데이터 준비와 학습 담당
  fishing_controller.py     # 게임 화면에서 best.pt로 찌를 찾는 담당
```

중요한 구분은 다음과 같습니다.

- `raw`는 원본 공책입니다. 스크립트는 이 폴더를 지우지 않습니다.
- `yolo11`은 연습용으로 다시 만든 복사본입니다. 다음 학습 때 지우고 새로 만듭니다.
- `best.pt`는 연습을 가장 잘한 모델입니다. 실제 낚시 감지기는 이 파일만 필요합니다.

## 4. 원본 라벨은 어떻게 생겼나요?

`annotations.csv`의 한 줄에는 이미지 이름, 상자의 왼쪽 위 좌표, 오른쪽 아래 좌표,
그리고 이름(`bb`)이 들어 있습니다.

```csv
image,xmin,ymin,xmax,ymax,label
WoWScrnShot_121722_144500.jpg,1162.56,564.01,1223.86,633.98,bb
```

이는 “이 그림에서 `x=1162`부터 `x=1223`까지, `y=564`부터 `y=633`까지가 찌예요”라는
뜻입니다. 현재 원본에는 **80개 라벨 행과 80장의 대응 이미지**가 있습니다.

YOLO11은 같은 정보를 조금 다른 모양으로 원합니다.

```text
0 0.62250000 0.33250000 0.03125000 0.04166667
```

각 숫자의 뜻은 `클래스 번호, 상자 가운데 x, 상자 가운데 y, 상자 너비, 상자 높이`입니다.
x와 y는 사진의 실제 픽셀이 아니라 0~1 사이의 비율입니다. 사진 크기가 달라져도
같은 규칙을 쓸 수 있기 때문입니다.

## 5. 학습 스크립트는 단계별로 무엇을 하나요?

### 5.1 명령 옵션 읽기

`parse_arguments()`는 사용자가 바꿀 수 있는 설정을 읽습니다.

- `--model yolo11s.pt`: 처음에 빌려 쓸 기본 YOLO11 모델입니다.
- `--epochs 100`: 전체 문제집을 100번 반복해서 보는 횟수입니다.
- `--imgsz 1280`: 모델에게 보여 줄 그림의 한 변 크기입니다. 작은 찌를 더 크게 보려는 설정입니다.
- `--batch -1`: GPU 메모리에 맞는 한 번의 학습 묶음 크기를 자동으로 고릅니다.
- `--val-ratio 0.2`: 80장 중 약 16장을 시험 문제로 떼어 둡니다.
- `--prepare-only`: 공부는 하지 않고 그림책과 정답지가 올바르게 만들어지는지만 확인합니다.

### 5.2 이미지 찾기

`find_images()`는 `data/bobber/raw/images` 아래를 재귀적으로 살펴봅니다.
즉, 안쪽 폴더에 넣어도 JPG, PNG, BMP, WEBP 파일을 찾습니다. CSV에 적힌 사진 이름이
실제로 없으면 즉시 멈추고 어떤 사진이 없는지 알려 줍니다. 없는 사진으로 공부하면
로봇이 엉뚱하게 배우기 때문입니다.

### 5.3 CSV를 읽고 클래스 번호 만들기

`read_annotations()`는 CSV의 `label` 값을 만나는 순서대로 숫자로 바꿉니다.
현재는 `bb` 하나뿐이므로 `bb = 0`입니다. 나중에 물고기나 UI 아이콘을 추가하면
각각 다른 번호를 받습니다.

### 5.4 YOLO 라벨로 변환하기

`prepare_dataset()`는 다음 일을 합니다.

1. 원본 이미지 이름을 섞습니다. 항상 같은 `--seed 42`를 쓰므로 다시 실행해도 같은
   학습/검증 분할을 만들 수 있습니다.
2. 약 80%는 `images/train`, 약 20%는 `images/val`에 복사합니다.
3. 각 상자의 픽셀 좌표를 0~1 비율의 가운데 좌표와 너비·높이로 바꿉니다.
4. 이미지마다 같은 이름의 `.txt` 라벨 파일을 만듭니다.
5. `data.yaml`을 만들어 Ultralytics에게 학습용·검증용 그림과 클래스 이름을 알려 줍니다.

복사본 파일명 앞에는 원본 경로의 SHA-1 일부를 붙입니다. 같은 이름의 사진이 다른
폴더에 있어도 서로 덮어쓰지 않게 하는 이름표입니다.

### 5.5 모델 학습하기

`train_model()`은 `YOLO("yolo11s.pt")`로 미리 일반 물체를 공부한 모델을 가져옵니다.
그 뒤 낚시찌 사진으로 추가 공부(fine-tuning)합니다. 처음부터 아무것도 모르는 모델을
가르치는 것보다 훨씬 적은 사진으로 시작할 수 있습니다.

학습 중 Ultralytics는 검증 성적을 비교하고, 가장 좋은 순간의 모델을
`runs/yolo11/bobber/weights/best.pt`에 저장합니다. 스크립트는 그 파일을
`models/bobber/best.pt`로 복사합니다. 그래서 실제 프로그램은 학습 기록 폴더를 찾지
않아도 됩니다.

## 6. 설치와 실행

반드시 **CPython 3.12.x**를 사용합니다. Python 3.14에서는 이전에 사용한 오래된 Pillow
패키지가 설치되지 않아 실패했습니다.

```powershell
py -3.12 -m pip install --upgrade pip
py -3.12 -m pip install -r requirements.txt

# 데이터셋만 만들고, 누락된 이미지나 라벨 오류가 없는지 먼저 확인
py -3.12 src/train_bobber_detector.py --prepare-only

# 실제 학습
py -3.12 src/train_bobber_detector.py
```

GPU가 없거나 문제가 있는지 확인하려면 다음처럼 CPU를 강제로 쓸 수 있습니다. CPU 학습은
매우 오래 걸릴 수 있습니다.

```powershell
py -3.12 src/train_bobber_detector.py --device cpu
```

NVIDIA GPU가 있다면 보통 `--device`를 생략하면 자동으로 사용합니다. 처음 실행할 때는
기본 모델인 `yolo11s.pt`를 내려받기 때문에 인터넷 연결이 필요할 수 있습니다.

## 7. 학습한 모델은 게임에서 어떻게 쓰이나요?

`fishing_controller.py`의 흐름입니다.

```text
WoW 창 캡처
   -> PIL/NumPy 이미지
   -> YOLO11 best.pt 예측
   -> 후보 상자 [x1, y1, x2, y2, class, confidence]
   -> 이전 찌와 가장 가까운 상자 선택
   -> 상자 중심의 세로 움직임 계산
   -> 충분히 큰 움직임이 연속되면 마우스 오른쪽 클릭
```

### 7.1 추론

`init_yolo()`는 `models/bobber/best.pt`를 한 번만 읽습니다. `detect_bobber()`는 매 화면에서
YOLO11에게 “찌가 있니?”라고 물어봅니다.

- 입력 크기는 1280입니다. 작은 찌가 너무 작아지지 않게 하기 위한 선택입니다.
- 신뢰도 기준은 `0.25`입니다. 모델이 25%보다 확신하지 못하면 후보에서 버립니다.
- 현재 데이터셋은 `bb` 클래스 하나이므로 클래스 번호 0만 사용합니다.

모델은 상자 좌표와 신뢰도를 여러 개 낼 수 있습니다. `select_bobber_box()`는 이전 프레임의
찌 중심과 가장 가까운 상자를 고릅니다. 이것은 화면의 다른 반짝임이나 잘못된 후보로
갑자기 갈아타지 않도록 하는 간단한 추적입니다.

### 7.2 움직임 판단

검출 상자의 중심이 위아래로 얼마나 움직였는지 계산합니다. 평소 움직임의 최근 중앙값을
기준으로 삼고, 현재 움직임이 기준의 6배 이상일 때 이상 움직임 후보로 봅니다. 한 번만
튀는 값으로 클릭하지 않도록 연속 2프레임을 요구합니다.

이 부분은 모델 자체가 아니라 **추적 규칙**입니다. 좋은 모델은 찌를 잘 찾고, 좋은 추적
규칙은 찾은 찌가 실제로 물에 잠긴 순간을 더 안전하게 판단합니다.

## 8. 성능은 어느 정도인가요?

아직 이 프로젝트에서 YOLO11 학습을 실행한 결과가 없으므로, 정확한 숫자를 말할 수
없습니다. 학습 전에는 “정확도 90%” 같은 수치를 약속하면 안 됩니다.

학습이 끝나면 `runs/yolo11/bobber` 안의 결과에서 다음을 확인합니다.

| 측정값 | 쉬운 뜻 | 좋을 때 |
| --- | --- | --- |
| Precision | 찌라고 말한 것 중 진짜 찌의 비율 | 거짓 경보가 적음 |
| Recall | 실제 찌 중 찾아낸 비율 | 찌를 놓치지 않음 |
| mAP50 | 상자가 정답 상자와 충분히 겹치는지의 종합 점수 | 1에 가까울수록 좋음 |
| mAP50-95 | 겹침 기준을 더 엄격하게 여러 번 검사한 종합 점수 | 더 까다로운 정확도 |
| 추론 시간 | 한 장을 찾는 데 걸리는 시간 | 작을수록 좋음 |

현재 데이터는 80장뿐이라 점수의 흔들림이 클 수 있습니다. 예를 들어 검증 사진 16장 중
몇 장만 다르게 맞혀도 점수가 크게 바뀝니다. 실전 성능은 비가 오거나, 물 반사가 다르거나,
카메라가 멀거나, UI가 겹친 실제 게임 장면에서도 따로 확인해야 합니다.

성능을 기록할 때는 최소한 다음을 남기세요.

```text
날짜 / 모델 이름 / 이미지 크기 / epoch / GPU 또는 CPU / mAP50 / mAP50-95 / 한 프레임 시간
```

## 9. 더 잘 만들려면 무엇을 해야 하나요?

가장 큰 개선은 새 모델 이름보다 **더 좋은 정답 사진**입니다.

1. **사진을 많이 모으기**: 최소 수백 장 이상을 목표로 합니다. 같은 장면이 연속된 80장만
   있으면 모델은 그 장면을 외우기 쉽습니다.
2. **어려운 장면 넣기**: 낮/밤, 맑음/비, 파도, 반사광, 다른 물 색, 다른 카메라 거리,
   UI가 겹친 장면을 넣습니다.
3. **없는 장면도 넣기**: 찌가 없는 물 화면을 넣으면 반짝임을 찌로 착각하는 일을 줄일 수
   있습니다. 단, YOLO 데이터셋에서는 이런 이미지에 빈 라벨 파일이 필요합니다.
4. **라벨 다시 확인하기**: 상자가 찌를 너무 크게 또는 작게 감싸면 모델도 그 습관을 배웁니다.
5. **학습/시험 장면 분리하기**: 거의 똑같은 연속 프레임이 학습과 검증에 함께 들어가면
   시험 성적이 실제보다 좋아 보입니다. 시간 구간이나 낚시 장소 단위로 나누는 편이 좋습니다.
6. **크기 비교하기**: `yolo11n`, `yolo11s`, `yolo11m`을 같은 데이터로 비교합니다. 작은
   모델은 빠르고, 큰 모델은 보통 더 많은 계산을 합니다.
7. **입력 크기 비교하기**: 찌가 작으면 1280이 유리할 수 있지만, 더 느립니다. 960과 1280을
   같은 검증 데이터로 비교합니다.
8. **신뢰도 기준 조절하기**: `CONFIDENCE_THRESHOLD` 0.25를 올리면 거짓 경보는 줄고 찌를
   놓칠 가능성은 늘어납니다. 실제 화면에서 0.20, 0.25, 0.35를 비교합니다.
9. **추적 규칙 측정하기**: 검출 성적과 클릭 성적은 다릅니다. 실제로 언제 클릭했는지를
   기록해, 거리 배수·연속 프레임 수를 조절합니다.

## 10. 자주 만나는 문제

### `ModuleNotFoundError: No module named 'PIL'`

Python 3.12 환경에서 설치 명령을 다시 실행합니다. Python 3.14의 `pip`이 아니라
`py -3.12 -m pip`을 써야 합니다.

### `YOLO11 checkpoint not found`

학습이 아직 끝나지 않았거나 `models/bobber/best.pt`가 없습니다. 먼저 학습 스크립트를
실행합니다.

### CSV는 있는데 이미지가 없다고 나옴

CSV의 `image` 열과 이미지 파일명이 같아야 합니다. 확장자, 공백, 철자를 확인합니다.

### 학습이 너무 느림

CPU 대신 GPU를 사용하고 있는지 확인합니다. 먼저 `yolo11n.pt`와 `--imgsz 960`으로 빠르게
동작을 확인한 뒤, `yolo11s.pt`, 1280으로 올립니다.

모델 크기는 Ultralytics 문서를 따릅니다. 지표의 일반적 정의는 COCO 평가 방식과 YOLO
